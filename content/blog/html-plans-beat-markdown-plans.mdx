Most agent harnesses write plans as Markdown checklists. It's the obvious choice — it's what models emit naturally and what humans read without thinking. It's also the reason plans go stale halfway through a long task.

## What a checkbox can actually encode

A Markdown task is one bit of state:

```md
- [ ] Migrate payouts to Inertia
- [x] Add sendgrid resend fallback
```

Done, or not done. Everything else a running task needs — who owns it, what it's blocked on, why it was abandoned, which attempt this is — has to live in prose beside the box, where nothing can read it reliably.

## The same plan as structure

```html
<task id="payouts-inertia" status="blocked" blocked-by="auth-refactor">
  <title>Migrate payouts to Inertia</title>
  <note>Waiting on the session shape to settle.</note>
</task>
```

    - a single node can be rewritten without touching the rest of the document
